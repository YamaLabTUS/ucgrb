# Migration from v5 to v7 (how to modify the input files)

## Summary

In September 2026, v7.0.0 was released, introducing the ΔkW-value version (balancing-market-aware) of the formulation.
In v7, the formulation style is switched with the setting value [`formulation_type`](../06_config/03_unit_commitment.md#formulation_type). The default value `"delta-kW-no-market"` behaves exactly the same as v5 (backward compatible).
Therefore, **the input CSV files and the configuration file (config.yml) used with v5 can be used with v7 as they are, without any modification, except for the check of the name column in Step 1** (there are no mandatory file-name or item-name changes).
Only when using the ΔkW-value version (`formulation_type: "delta-kW-bid"`) do you need to add items to the input files, following Step 3 and later.

## Step 1: Check that no non-ASCII characters are used in the name column (mandatory)

In v7, only ASCII characters (alphanumeric characters and symbols) are allowed in the name columns (generators, ESS, areas, tie lines, planned outages, etc.); see "[How to describe power system data CSV files](../05_csvfile/01_about.md#regarding-data-validation)".
If you were using names containing non-ASCII characters such as Japanese, you need to change them to alphanumeric names.

- If non-ASCII characters are included, an error occurs when the CSV file is read, and the name of the CSV file, the column name and the invalid values (with the row numbers in that file) are displayed.
- CSV files without a name column (time series data, etc.) are not checked.

## Step 2: Using the same problem settings as v5 (no other modification required)

If `formulation_type` is not described in config.yml, the program runs with the default value `"delta-kW-no-market"`, which is the same formulation as v5.

- There are no changes to CSV file names or item names.
- There are no renames of existing items in config.yml.

Steps 3 to 6 below are required only when using the ΔkW-value version (`"delta-kW-bid"`).

## Step 3: Add `formulation_type` to config.yml

To use the ΔkW-value version, add the following to config.yml.

```yaml
formulation_type: "delta-kW-bid"
```

- The only allowed values are `"delta-kW-no-market"` (default) and `"delta-kW-bid"`. Specifying any other value raises an error.
- For details, see "[UC Problem Setting](../06_config/03_unit_commitment.md#formulation_type)" and "[Configuration file examples (Example 14)](../03_01_run_with_licence/02_example.md)".

## Step 4: Add items to generation.csv

In the ΔkW-value version, add the following items to generation.csv.
In the input CSV files for the Ministry of the Environment project, generation\_\_01\_thermal.csv, generation\_\_02\_nuclear.csv, and generation\_\_03\_hydro.csv are the files to be modified.

| Item name to add | Summary                                                                                                        | thermal or nuclear | hydro | Value filled in if the column is absent |
| :--------------- | :------------------------------------------------------------------------------------------------------------- | :----------------- | :---- | :-------------------------------------- |
| C_Delta_kW_UP    | Up-direction reserve capacity (ΔkW) unit price [Thousands of yen/MWh/h]                                        | ✓                  | ✓     | 0                                       |
| C_Delta_kW_DOWN  | Down-direction reserve capacity (ΔkW) unit price [Thousands of yen/MWh/h]                                      | ✓                  | ✓     | 0                                       |
| C_fuel_kWh_UP    | Up-direction reserve energy (kWh) unit price [Thousands of yen/MWh] (before considering the internal consumption rate)   | ✓                  | N.A.  | C_fuel                                  |
| C_fuel_kWh_DOWN  | Down-direction reserve energy (kWh) unit price [Thousands of yen/MWh] (before considering the internal consumption rate) | ✓                  | N.A.  | -1 × C_fuel                             |
| C_kWh_UP         | Up-direction reserve energy (kWh) unit price [Thousands of yen/MWh]                                            | N.A.               | ✓     | 0                                       |
| C_kWh_DOWN       | Down-direction reserve energy (kWh) unit price [Thousands of yen/MWh]                                          | N.A.               | ✓     | 0                                       |

- If a column is absent, no error is raised; the value in the table above is filled in automatically, and the missing column names are output to a WARNING log.
- In `"delta-kW-no-market"` (default), these columns are not read, so adding them does not affect the default behavior.
- For details on each item, see "[Generator data](../05_csvfile/02_generation.md)".

## Step 5: Add items to ESS.csv

In the ΔkW-value version, add the following items to ESS.csv.

| Item name to add | Summary                                                                   | Value filled in if the column is absent |
| :--------------- | :------------------------------------------------------------------------ | :-------------------------------------- |
| C_Delta_kW_UP    | Up-direction reserve capacity (ΔkW) unit price [Thousands of yen/MWh/h]   | 0                                       |
| C_Delta_kW_DOWN  | Down-direction reserve capacity (ΔkW) unit price [Thousands of yen/MWh/h] | 0                                       |
| C_kWh_UP         | Up-direction reserve energy (kWh) unit price [Thousands of yen/MWh]       | 0                                       |
| C_kWh_DOWN       | Down-direction reserve energy (kWh) unit price [Thousands of yen/MWh]     | 0                                       |

- The behavior when a column is absent is the same as in Step 4 (the default value is filled in and a WARNING log is output).
- For details on each item, see "[Generator data - Energy storage systems](../05_csvfile/02_generation.md#energy-storage-systems)".

## Step 6: Specify `optimization_timing` explicitly when describing rolling_opt_list directly

In v7, the item [`optimization_timing`](../06_config/04_rolling_optimization_list.md#optimization_timing) was added to each element of rolling_opt_list, indicating whether that round of optimization is day-ahead scheduling (`"day-ahead"`) or intra-day scheduling (`"intra-day"`).
The ΔkW-value version switches the tertiary-reserve formulation according to this time axis (ΔkW value in day-ahead scheduling, kWh value in intra-day scheduling), so when you describe rolling_opt_list **directly**, specify `optimization_timing` explicitly in each element.

```yaml
rolling_opt_list:
  - name: "day_ahead_scheduling"
    # ... (same descriptions as before) ...
    optimization_timing: "day-ahead"
  - name: "intra_day_scheduling"
    # ... (same descriptions as before) ...
    optimization_timing: "intra-day"
```

- When rolling_opt_list is generated automatically with `start_date` or `start_month`, this item is assigned automatically to each round, so there is no need to describe it.
- In `"delta-kW-no-market"` (default), it is not referenced and can be omitted (default value `"day-ahead"`).

## Note: Optional settings added after v5.0.0

Apart from the ΔkW-value version, the following setting values have been added since the release of v5.0.0. Each of them has a default value, so describing them in config.yml is optional and the configuration files used with v5 work without modification.

| Setting value | Description | Default value |
| :--- | :--- | :--- |
| [`grb_NodefileStart`](../06_config/02_input_data_and_solver.md#grb_nodefilestart) | The amount of memory [GB] at which Gurobi starts writing MIP nodes to disk | Half of the physical memory of the machine (8.0 GB if the detection fails) |
| [`grb_Threads`](../06_config/02_input_data_and_solver.md#grb_threads) | The number of CPU threads used by Gurobi | `0` (detected automatically by Gurobi) |

In addition, leading and trailing spaces in the column names and the string data of CSV files are now trimmed automatically. No modification of the existing input files is required.
