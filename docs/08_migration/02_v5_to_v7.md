# v5からv7への移行（入力ファイルの変更方法）

## 概要

2026年9月、ΔkW価値考慮版（需給調整市場考慮）の定式化を導入したv7.0.0を公開した。
v7では、定式化のスタイルを設定値[`formulation_type`](../06_config/03_unit_commitment.md#formulation_type)で切り替える。既定値`"delta-kW-no-market"`はv5と同一の挙動（後方互換）である。
そのため、**v5で用いていた入力CSVファイル・設定ファイル（config.yml）は、手順1のname列の確認を除き、修正せずにそのままv7で利用できる**（ファイル名・項目名の必須変更は無い）。
ΔkW価値考慮版（`formulation_type: "delta-kW-bid"`）を利用する場合のみ、手順3以降に従って入力ファイルに項目を追加する必要がある。

## 手順1: name列にASCII文字以外が使われていないかの確認（必須）

v7では、name列（発電機・ESS・地域・連系線・計画停止等）にASCII文字（英数文字と記号）のみ使用可能である（「[電力系統データCSVファイルの記述方法](../05_csvfile/01_about.md#データバリデーションに関して)」参照）。
日本語等の非ASCII文字を含む名称を使用していた場合は、英数字の名称へ変更する必要がある。

- 非ASCII文字が含まれている場合、CSVファイルの読み込み時にエラーとなり、対象のCSVファイル名・列名・該当する値（当該ファイルの行番号付き）が表示される。
- name列を持たないCSVファイル（時系列データ等）は検査の対象外である。

## 手順2: v5と同じ問題設定で利用する場合（その他の修正は不要）

config.ymlに`formulation_type`を記載しない場合、既定値`"delta-kW-no-market"`として動作し、v5と同一の定式化となる。

- CSVファイルのファイル名・項目名の変更は無い。
- config.ymlの既存項目の名称変更は無い。

以降の手順3〜6は、ΔkW価値考慮版（`"delta-kW-bid"`）を利用する場合のみ必要である。

## 手順3: config.ymlへの`formulation_type`の追加

ΔkW価値考慮版を利用する場合、config.ymlに以下を追加する。

```yaml
formulation_type: "delta-kW-bid"
```

- 設定可能な値は`"delta-kW-no-market"`（既定）と`"delta-kW-bid"`の2つのみ。それ以外の値を指定するとエラーとなる。
- 詳細は「[UC問題設定](../06_config/03_unit_commitment.md#formulation_type)」および「[コンフィグファイルの記述例（例14）](../03_01_run_with_licence/02_example.md)」を参照。

## 手順4: generation.csvへの項目追加

ΔkW価値考慮版では、generation.csvに以下の項目を追加する。
環境省プロジェクトの入力CSVファイルではgeneration\_\_01\_thermal.csv、generation\_\_02\_nuclear.csv、generation\_\_03\_hydro.csvが修正対象となる。

| 追加項目名      | 概要                                              | thermal or nuclear | hydro | 列が無い場合の補完値 |
| :-------------- | :------------------------------------------------ | :----------------- | :---- | :------------------- |
| C_Delta_kW_UP   | 上げ方向調整力（ΔkW）単価 [千円/MWh/h]            | ✓                  | ✓     | 0                    |
| C_Delta_kW_DOWN | 下げ方向調整力（ΔkW）単価 [千円/MWh/h]            | ✓                  | ✓     | 0                    |
| C_fuel_kWh_UP   | 上げ方向調整電力量（kWh）単価 [千円/MWh] （所内率考慮前） | ✓                  | N.A.  | C_fuel               |
| C_fuel_kWh_DOWN | 下げ方向調整電力量（kWh）単価 [千円/MWh] （所内率考慮前） | ✓                  | N.A.  | -1 × C_fuel          |
| C_kWh_UP        | 上げ方向調整電力量（kWh）単価 [千円/MWh]          | N.A.               | ✓     | 0                    |
| C_kWh_DOWN      | 下げ方向調整電力量（kWh）単価 [千円/MWh]          | N.A.               | ✓     | 0                    |

- 列が存在しない場合はエラーとならず、上表の補完値が自動的に入力され、欠損列名がWARNINGログに出力される。
- `"delta-kW-no-market"`（既定）ではこれらの列は読み込まれないため、追加しても既定の動作には影響しない。
- 各項目の詳細は「[発電機データ](../05_csvfile/02_generation.md)」を参照。

## 手順5: ESS.csvへの項目追加

ΔkW価値考慮版では、ESS.csvに以下の項目を追加する。

| 追加項目名      | 概要                                     | 列が無い場合の補完値 |
| :-------------- | :--------------------------------------- | :------------------- |
| C_Delta_kW_UP   | 上げ方向調整力（ΔkW）単価 [千円/MWh/h]   | 0                    |
| C_Delta_kW_DOWN | 下げ方向調整力（ΔkW）単価 [千円/MWh/h]   | 0                    |
| C_kWh_UP        | 上げ方向調整電力量（kWh）単価 [千円/MWh] | 0                    |
| C_kWh_DOWN      | 下げ方向調整電力量（kWh）単価 [千円/MWh] | 0                    |

- 列が存在しない場合の挙動は手順4と同一（補完値の入力とWARNINGログ出力）。
- 各項目の詳細は「[発電機データ - エネルギー貯蔵システム](../05_csvfile/02_generation.md#エネルギー貯蔵システム)」を参照。

## 手順6: rolling_opt_listを直接記述する場合の`optimization_timing`の明示

v7では、rolling_opt_listの各要素に、その回の最適化が前日計画（`"day-ahead"`）か当日計画（`"intra-day"`）かを示す項目[`optimization_timing`](../06_config/04_rolling_optimization_list.md#optimization_timing)が追加された。
ΔkW価値考慮版はこの時間軸に応じて三次調整力の定式化を切り替える（前日計画はΔkW価値、当日計画はkWh価値）ため、rolling_opt_listを**直接記述**する場合は各要素に`optimization_timing`を明示する。

```yaml
rolling_opt_list:
  - name: "day_ahead_scheduling"
    # ...（従来通りの記述）...
    optimization_timing: "day-ahead"
  - name: "intra_day_scheduling"
    # ...（従来通りの記述）...
    optimization_timing: "intra-day"
```

- `start_date`や`start_month`によるrolling_opt_listの自動生成を利用する場合は、各回に自動付与されるため記載不要。
- `"delta-kW-no-market"`（既定）では参照されないため省略可能（既定値`"day-ahead"`）。

## 補足: v5.0.0以降に追加された任意設定

ΔkW価値考慮版とは別に、v5.0.0の公開以降、以下の設定値が追加されている。いずれも既定値が用意されているため、config.ymlへの記載は任意であり、v5で用いていた設定ファイルは無修正で動作する。

| 設定値 | 内容 | 既定値 |
| :--- | :--- | :--- |
| [`grb_NodefileStart`](../06_config/02_input_data_and_solver.md#grb_nodefilestart) | GurobiがMIPのノードをディスクに書き出し始めるメモリ量 [GB] | 起動計算機の物理メモリの半分（検出に失敗した場合は8.0 GB） |
| [`grb_Threads`](../06_config/02_input_data_and_solver.md#grb_threads) | Gurobiが使用するCPUスレッド数 | `0`（Gurobiが自動的に検出） |

また、CSVファイルの列名および文字列データについて、先頭・末尾の空白が自動的に取り除かれるようになった。既存の入力ファイルに対する修正は不要である。
